# Опис API та сценарії застосування

Google Cloud Vision — керований сервіс аналізу зображень. Окрім OCR, API підтримує визначення міток зображення, логотипів, пам’яток та інших ознак. У цьому PoC реалізовано лише OCR.

## Обрані операції

Обидва режими використовують `POST /v1/images:annotate`.

| Режим | Призначення | Результат Google |
|---|---|---|
| TEXT_DETECTION | Написи на фото, короткі фрагменти | Загальний текст, слова та координати |
| DOCUMENT_TEXT_DETECTION | Щільний текст на зображеннях документів | Структура сторінок, блоків, абзаців і слів |

Програма показує лише суцільний текст. Вона не малює bounding boxes, не відновлює таблиці та не інтерпретує зміст документа. Модель надає Google, її навчання та ваги не входять у проєкт.

## Локальні маршрути

| Метод / шлях | Вхід | Вихід |
|---|---|---|
| GET `/` | — | HTML-інтерфейс |
| GET `/api/status` | — | Лише факт наявності ключа, без його значення |
| POST `/api/ocr?feature=TEXT_DETECTION` | Двійкові PNG/JPEG, заголовок `X-OCR-Client: local-poc` | `text`, `mode=live`, `elapsed_ms`, `feature` |
| POST `/api/demo` | Той самий заголовок | Фіксований навчальний текст, `mode=demo`, `elapsed_ms=null` |

Локальний статус 502 означає проблему із зовнішнім API або його конфігурацією. Повідомлення розрізняють HTTP 400, 401, 403, 429 та помилки сервісу. Секретний ключ і сирі винятки зовнішнього клієнта не передаються в браузер. Автоматичних повторів немає, щоб не створювати неочікувані повторні запити.

## Сфери застосування

1. Оцифрування навчальних конспектів: зображення сторінки стає текстом для пошуку.
2. Первинне введення даних із чеків і рахунків: OCR витягає символи, окремий модуль має виділити суму, дату та номер.
3. Доступність: отриманий текст можна передати окремому сервісу синтезу мовлення.
4. Пошук написів на зображеннях: наприклад, назви або інформаційні таблички.

Ці сценарії є можливими напрямами використання API. PoC не є готовою бухгалтерською системою чи системою розпізнавання номерних знаків.

## Обмеження

Погане освітлення, поворот, дрібні символи та розмиття можуть знижувати точність. Результат слід перевіряти вручну. Вимірювання точності на реальних даних ще не виконано. Для подальшого дослідження варто взяти 10–20 зображень із вручну записаним еталоном і обчислити CER = (заміни + видалення + вставки) / кількість символів еталона, окремо задавши правила пробілів і перенесень рядків.

Офіційні ліміти сервісу: до 20 MB на зображення та до 10 MB на JSON-запит. Base64 збільшує обсяг приблизно на третину. Власне обмеження 4 MiB залишає запас для JSON. Це не повна перевірка обмежень Google за розмірами зображення у пікселях.
